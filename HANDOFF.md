## How to test locally (this machine)
- Use **`serve2.ps1`** — PowerShell HttpListener, `-Port` param (default **8742**), serves this folder AND accepts **POST /save?name=x.jpg** (body = base64 → written beside the server; the page can `fetch('/save?...',{method:'POST',body:b64})` to hand canvas screenshots to the session even when the Browser pane is hidden and `computer screenshot` times out). `serve.ps1` is the older fixed-8741 version, no /save.
- `.claude/launch.json` (at `C:\Users\deove\.claude\.claude\launch.json`) has a `tiny-conquerors` entry → `preview_start {name:'tiny-conquerors'}` starts serve2 on 8742.
- The raw file needs a wrapper for local testing (artifact wrapper adds doctype/viewport). Build `test.html` like:
  `$c=[IO.File]::ReadAllText("...\tiny-conquerors.html"); [IO.File]::WriteAllText("...\test.html","<!doctype html><html><head><meta charset=`"utf-8`"><meta name=`"viewport`" content=`"width=device-width, initial-scale=1, user-scalable=no`"></head><body>"+$c+"</body></html>")`
- Navigate to http://localhost:8742/test.html?v=N (bump N — cache-buster) in the Browser pane.
- **Headless testing pattern that works well:** `javascript_tool` → `document.getElementById('startBtn').click()` then call `step(0.05)` in loops to fast-forward the simulation (12k steps = 10 game-min), inspect `G` directly. `draw()` renders one frame. `G.vis.fill(2); fogDirty=true` reveals the map for screenshots. Buttons: `.diff button[data-d=0|1|2]` difficulty, `[data-m=0|1|2]` map, `[data-n=2..8]` players, `[data-t]` teams, `[data-tb=0|1]` turbo; set global `civSel` before clicking start.
- **⚠ The javascript_tool has a 30s limit and a timeout RELOADS the page, losing the game.** Measured step cost on this machine: 2p ~0.07ms, 8p River (128) ~1.2ms, **8p Hallowed Ground (128) ~9.4ms** — so a game-minute (1200 steps) is 0.1s / 1.4s / **11s** respectively. Budget by map: ~3 game-minutes per call is safe on River, but **only ~2 on Hallowed Ground**. Long runs cost me four wasted cycles.
  - That 8x spread is Hallowed Ground itself (a wide-open 128² board, almost certainly A* cost), not a regression — verified by re-measuring with the wildlife stubbed out. It is the map to profile if 8p ever feels heavy in real play; ~9.4ms against a 50ms step still leaves 5x headroom.
- **Prefer a targeted scenario over a whole-game sim.** The villager-stacking bug was invisible in whole-game overlap counts and obvious the moment I put 10 villagers on one tree. Same for combat: spawn the two units you care about and step 200 times.
- **Determinism check (run after ANY sim change):** `pendingSeed=N; newGame(); for(...)step(0.05); stateHash()` twice → hashes must match. See MULTIPLAYER.
  - Stronger, and worth it for any broad refactor: **build a page from the previous commit and run both head-to-head.** `git show HEAD:tiny-conquerors.html` → wrap as `test-old.html` → run the same scenarios on both and compare hashes. That is how the ~200-site `localP` sweep was proved behaviour-preserving (7 scenarios: 3 maps, 2/3/4/8 players, 3 team modes, 3 civs — all identical).
  - **Baselines as of tq-v73** (diffSel 1, civSel 0, turboSel 0, teamSel 0 unless stated, no mission), seed/steps → hash: `m0-2p` 4242/1500 → `6825c2e`; `m1-2p` 4242/1500 → `6fdc60a7`; `m2-2p` 4242/1500 → `c39be881`; `m1-8p-2team` (teamSel 1) 31337/1500 → `4f8eb0e0`. The game auto-points at `ws://localhost:8080` when served from localhost and at the deployed relay otherwise — no config to change. Two Browser-pane tabs, then the pump recipe under MULTIPLAYER § Test recipe.

## Architecture (all in the one <script>)
- **Constants:** MAP (let) = **96 / 112 / 128 by player count, Black Forest one size down; 128 is the hard ceiling** (canvas limit — see "bigger-maps"), TILE=26, AGES/AGE_COST (manual values; `ageCostOf(p,age)` applies civ discounts), **UNITS (47: land, 8 ships, 3 wild animals)** with `line:{}` per-age upgrade lines and `elite:{}` Imperial stats — **`statFor(type,p)` is the single stat resolver** (addUnit/atkOf/rangeOf/rofOf/unitName all use it), **CIVS (18, manual bonuses; first 12 order FROZEN for save compat)**, **UTECHS** (19 unique techs, castle-researched), **BS_TECHS** (blacksmith 5 lines × 3 tiers; armor = flat damage reduction via `bsArmorOf`), BLDS (tc/house/farm/camp/barracks/range/stable/siege/castle/tower/market/monastery/blacksmith/dock/**university**/**wonder**/walls/gates), DIFF, `IHT` sprite heights (**every new building type needs an entry or portraits crash**), `trainsFor(b,p)` = single source of trainable units.
- **Tech/bonus tables** (all added post-manual): `UNI_TECHS`+`hasUni` (University, 8), `ECO_TECHS`+`ecoTier`/`ecoMax` (economy + monastery + line techs, 24 entries keyed by home `bld`), `TEAM_BONUS`+`teamHas(p,key)` (per-civ, shared with allies), `BUILD_TABS`{eco,mil,def}+`buildTab` (**a new building MUST be added to a tab or it is unreachable by touch**).
- **Determinism (multiplayer):** `SR()`/`SRi(n)` seeded by `seedSim(gameSeed)` — the only randomness allowed to touch G. `stateHash()` fingerprints the sim. `uid=1` reset in newGame is load-bearing. See the MULTIPLAYER section.
- **Command layer (multiplayer step 2):** defined right after `cmdBuild`. `issue(k,d)` → `cmdQ` → `drainCmds()` → `applyCmd` → the `CMDS` handler table. **Every human action goes through it; nothing in the UI mutates G directly any more.** `netMode=false` makes `issue()` drain immediately (solo play, zero added latency); `step()` also drains at the top so a networked tick has one defined application point. `applyTick(perPlayer)` is the lockstep entry. `cmdUnits(c)` resolves ids by walking **G.units** (not `c.u`) so peers visit them in the same order. Handlers re-validate everything — see MULTIPLAYER.
- **Wildlife:** `const GAIA=8` (player slots are 0..7, so 8 is always free). `G.P`/`G.teams`/`G.ais` are **padded to index GAIA in newGame AND loadGame** — a hole there makes `stateHash`'s `G.P.map` throw. `isAnimal(u)`, `UNITS.sheep/deer/boar` (`animal:true` + `herd`/`skittish`/`fierce`), `placeAnimals()` (called from genMap), `dropCarcass(u)`, `animalHit(t,from)`, `BEAST` + `drawBeastRig`. States `graze`/`flee` at the top of updateUnit's switch.
- **State `G`:** units[], blds[], res{} (types wood/food/gold/**fish**), map[][], water{}, ford{}, **navBlock{}** (dock footprints — ships route around), elev, wallMap/gateMap, vis, P[NP] (res, age, civ, **uts[], bs{}, pt**), ais[], teams[], relics[], groups{}, wonderT/relicT (victory countdowns), fx/corpses/rubble/stuck/pings/proj, cam, sel[], inspect, placing/pend/wallA/pendLine.
- **Sim:** fixed 0.05s steps in `step(dt)`; `updateUnit` state machine (idle/move/attack/amove/toRes/gather/toFarm/farming/return/toBuild/building/toGar/toGarU/toHeal/heal/toRelic/toMon/toConv/convert/tradeOut/tradeBack/**graze/flee** — the last two are wildlife). A* `findPath(sx,sy,tx,ty,team,naval)` — **all unit repaths go through `uPath(u,tx,ty)`** (ships auto-naval via `passableW` = water/ford minus navBlock). Rams/transports carry passengers in `u.gar` (garrison finalized AFTER the unit loop — never splice mid-iteration).
- **AI (`aiThink`)**: villager jobs, houses (skipped for Huns), camps, military buildings by age, blacksmith + tech buying, dock near closest `G.waterList` tile (25s cooldown), unique-tech research at castle, fishing ships auto-fish, attack waves with persistent targets.
- **Rendering:** ISOMETRIC. Terrain flat-painted then skewed; buildings pre-rendered iso sprites (`ISO_ART`+`mkIsoSpr`); units procedural rigs (`drawManRig`/`drawHorseRig` + MAN_COSTUME/CAV_COSTUME, `drawWarWagon`/`drawShip` diagonal-snapped, `drawElephantRig`, `drawRam`), y-sorted with resource billboards (`getResSpr` incl. fish). Portraits render through drawUnitBody into cached dataURLs.
- **Sound:** WebAudio synth (`snd(kind)`), compressor bus, ambient birds; `initAudio()` on start tap.
- **Input:** tap select/command; right-click commands (mouse); box select; double-tap select-type; pinch/wheel zoom; minimap diamond tap; wall line placement; Ctrl+1-9 groups. `BUILD_KEYS` (blacksmith S, dock D), `TRAIN_KEYS_BY_BLD`, castle U = unique unit. Start screen: Begin the Conquest / Campaign (8 missions) / **Play with Friends** (the multiplayer lobby) / Continue.

## Balance/behavior notes
- Stats follow the manual's Unit Attributes tables (pp. 42-44); lines upgrade by age; unique units go Elite at Imperial.
- High ground: +25% dmg attacking downhill, −20% uphill.
- Rams: building-only (2 vs units), arrows capped at 2 vs them; garrisoned infantry add +8% speed/+5 atk each.
- Counters: spearman +10 vs cav, skirmisher +5 vs ranged, mameluke +9 vs cav, jaguar +10 vs infantry, cataphract +6 vs infantry, samurai +5 vs unique units, fire ship +3 vs ships, huskarl/eagle arrowRes .5/.7, petard/demo self-destruct blasts.

- Wave pacing per DIFF; Squire deliberately gentle (firstWave 380s).
- Win/lose = destroy all enemy Town Halls (allies may survive).

## Hard-won gotchas (do not regress)
1. **Radius margins:** every "am I close enough" check needs slack for diagonal corners + crowd push (gather 1.8, farm 1.85, deposit size*.5+1.7, build size*.5+1.7, melee vs building 1.3). Tight radii caused villager deadlocks twice.
2. `canPlace(tx,ty,size,margin,allowFord)` — AI uses margin 1 so it never walls itself in; walls/gates use allowFord.
3. Sprite caches (`ISPR`/`RES_SPR`/`PORTRAITS`/`CORPSE_SPR`) are per-page-load and key on type/team/built/stage — art changes take effect on reload, no busting needed at runtime; but a NEW key dimension (like house `vr`) must be added to the cache key or variants collide.
4. Fog alphas tuned for phone visibility (unexplored 208, explored 84) after a "screen is all dark" complaint — don't darken again.
5. The artifact CSP blocks all external requests — everything must stay inline.
6. **A new player action must be a command.** Adding a button that calls `pay()`/`addBld()`/`cmdX()` inline silently reopens the hole step 2 closed. Add a `CMDS` handler and `issue()` it; keep the toast/greying-out in the UI, put the authority in the handler.
7. **Anything that scans units must decide about wildlife.** Already guarded: `nearestEnemy` (or soldiers abandon battles to shoot sheep), `canConvert`, `updateFog` (owned sheep see 3 tiles — deliberate, they're scouts), `popUsed`, `updateArmyCounts`, Select-army, `cycleIdleMil`, the monk heal scan, the AI's `army` list and its town-defense `danger` check (a boar in the fields is not an invasion). `dealDamage`'s raid warning special-cases `fromP===GAIA`.
8. **`u.p` is not a real player index for wildlife.** `CIVS[G.P[GAIA].civ]` resolves to Britons, which is harmless but means any message built from `CIVS[...].name` must check for GAIA first.

The client says exactly that instead of pretending otherwise. Upgrading to Starter ($7/mo) removes it — offered to the user, who chose Free for now.
- Deliberate design: the relay knows about rooms, seats and opaque blobs and NOTHING about the game. Putting rules in it would mean two implementations to keep in step, which is the thing lockstep exists to avoid.
- **Seats come from the socket, never the message** — a `cmds` frame is re-stamped with the sender's real seat, so a modified client cannot order another player's army. The game's `CMDS` handlers check ownership again on arrival.

### Client pieces
- **`localP`** — the local player is no longer slot 0. The sim was always player-indexed; the VIEW was not. Resource bar, panel, fog, minimap, warnings, score list, selection, ownership, win test and mission setups all read `localP` now. `humanSlots` decides which seats get an AI; `netCivs`/`netTeams` let the lobby pick civs and sides. `resetNet()` puts the seat back to solo and is called from every non-network start path.
  - **`face:p===0?1:-1` in addUnit is deliberately NOT localP** — it is written into the unit record, so keying it to the viewer would have two peers build different units.
- **Lockstep** (`NET_LAG=5` turns = 250ms): orders are scheduled 5 turns ahead; a turn runs only when every peer's list for it has arrived. Falling behind stalls everyone — that is the point — and after 2.5s the others are told who they're waiting for. Hashes go out every 20 turns.
- **`drainCmds()` no-ops in netMode** — the queue is shipped, not applied locally, or every order would execute twice on one machine.
- **Failure handling**: a desync halts both peers within a second with a message that does not blame the player's connection.
- **A dropped player's seat passes to the computer** (sw tq-v26). The whole trick is that every machine must flip on the SAME turn:
  - Only the relay knows a socket died, so **the relay names the turn**: `maxTurn + AI_TAKEOVER_DELAY(20)`, broadcast as `{t:'ai',seat,turn,name}`. That turn is always in everyone's future, because no peer can have executed past the leaver's last command yet.
  - Filling the gap between that last command and the takeover turn rests on **WebSocket delivery being ordered**: by the time a peer gets the notice, everything the leaver DID send has already arrived. So `netSeatCmds` treats a missing list for a `netGone` seat as empty, and every peer fills the same blanks with the same nothing.
  - Handovers are walked **in seat order, not Map order** (`for(let s=0;s<NP;s++)if(netAiAt.get(s)===netTurn)`) — Map iteration order is one more thing two machines could disagree about.
  - `netSeatToAI` seeds the AI from values identical on every peer (`G.t+90`, `.1*seat`); `nextAtk` is in `stateHash`, so it has to match exactly.
  - **When the LAST opponent goes, `netGoOffline()` drops to a plain offline game** rather than depending on a relay nobody is on the other end of. **Gotcha found in testing:** that transition beats the takeover turn, so `netRunTurn` never comes round to honour it and the abandoned seat sat there as a dead town. `netGoOffline` now applies every pending handover on its way out — there is nobody left to disagree with. It also flushes the player's own in-flight commands so the last 250ms of orders aren't binned.
  - Verified three-peer on a local relay (both survivors flipped on turn 3016 and were still on identical hashes 1400 turns later, AI-grown town matching on both) and again two-peer against the deployed relay from the live site.
- **Reconnect: DONE** (sw tq-v28). Enter the same room code and you get your seat back — towns, army, wherever the computer left them.
  - **By REPLAY, not by shipping state.** The relay journals every non-empty command list plus every seat handover; the returning peer rebuilds the match from turn 0. Measured 159-709x real time (4,806 turns in 1.0s; 40,005 in 13.2s), so even a long absence costs seconds.
  - **Shipping a saved game does NOT work, and it fails deceptively.** A snapshot reloads to an *identical* hash and then diverges the moment it is stepped, because `saveGame` strips unit paths and `loadGame` re-seeds the RNG from the original seed. Verified: hash matches at load, then the branches part on the very next 100 turns. So the older handoff line "save/load round-trips to the same hash" is true but means less than it looks — **it does not mean a loaded game continues identically.**
  - **The journal/live-stream seam is the fiddly part.** Peers send turns in strictly increasing order, so the journal is complete through the highest turn EVERY present seat has sent for — the relay computes that as `cut` and the replay covers `0..cut` INCLUSIVE. Above the cut a seat that had run ahead already sent turns the rejoiner will never be shown (and empty ones were never journalled), so the relay also hands over per-seat `sentUpTo` marks and those gaps are filled with empty. Get either wrong and the rejoin stalls forever waiting for a message nobody will send — both were real bugs found in testing.
  - **`netSendFrom`** is the first turn this machine answers for; null while an AI holds the seat, so a spectating rejoiner sends nothing (sending would race the peers — some using its list, some the empty one the seat's absence implies). It is set when the `human` message ARRIVES, not when the turn is reached, or the others hit the changeover turn with nothing from us.
  - Handovers resolve BEFORE a turn works out whose orders it needs, since they change the answer.
  - Verified on the live site: dropped, AI held the seat, rejoined and replayed in 1.0s, seat back at the agreed turn, both peers on identical hashes afterwards.
- **PRODUCTION-ONLY GOTCHA — a closed socket raises no event through Render's proxy.** Locally `ws.on('close')` fires instantly; on the deployed relay the server sees *nothing*, and the room still reported two players seconds after one had closed. The only thing that reveals the corpse is a missed heartbeat, so drop detection is entirely down to the ping interval. With the original 30s ping that was up to a minute of everyone stalled. Now 5s pings, 3 misses allowed → **~10-20s, measured 10.1s on production**. Anything else built on this relay must not assume `close` arrives, and a test that only runs against localhost will never show it.
- **If the relay restarts, in-flight matches end.** Rooms are in memory; Render's free tier restarts on deploy and spins down when idle. Nothing recovers a match from that — the room code is simply gone.
- **The artifact cannot do multiplayer** — its CSP blocks all outbound connections. `netAvailable()`/the socket error message point at the web app.

He was given four options (pre-rendered 3D→sprites, harder 2D shading, 3D units over 2D world, full rewrite) with the trade-offs, and **chose the full 3D rewrite** knowing it is a multi-session job that replaces the renderer and the art direction. **The one architectural rule: the 3D renderer is built BESIDE the 2D one, never instead of it.** `use3D` + the `#d3Btn` button swap `body.r3d`, which shows `#view3` and hides `#view`. Reasons, in order of importance:
1. The previous from-scratch attempt (`../tiny-engine`) was parked at step 2 with "that's worse, go back to the old game." A toggle makes every stage directly A/B comparable against the thing it is replacing, so "worse" is visible immediately rather than at the end.
2. The game stays playable and shippable at every commit.
3. **The simulation must not be touched.** Determinism baselines are the proof — re-run them after every stage. Multiplayer survives the rewrite for free precisely because rendering is not in the hash.

**Camera — the key idea.** The vertex shader reproduces the EXISTING 2D projection exactly rather than inventing a 3D camera:
`screenX=((wx-wz)*IW-cam.x)*zoom`, `screenY=((wx+wz)*IH-height-cam.y)*zoom` — i.e. what `isoPt()` + the ctx transform in `draw()` already do. Consequences worth keeping: both renderers frame the world identically (so screenshots can be diffed), and **every screen-space system keeps working untouched** — tap hit-testing, the minimap, `clampCam`, box select. Do not replace this with a conventional lookAt/perspective camera without a plan for all of those.

- **Raw WebGL, no library.** The artifact CSP blocks external scripts and the game must stay one self-contained file; inlining three.js would add ~600KB. `R3` is ~150 lines and lives just above `frame()`.
- **✅ DECIDED 2026-08-07: THE CAMERA ROTATES AND TILTS. Commit to real geometry everywhere.** Daniel was shown the finding below and chose "Rotate + tilt — commit to real 3D", accepting that it invalidates the Stage-1 camera and the screen-space systems built on it. **Consequences already landed:** the hard-coded 2D projection is gone from the shaders, replaced by a real orthographic `lookAt` matrix (`R3.mvp()`, `m4ortho`/`m4look`/`m4mul`). Home orientation is the classic isometric one — yaw 45°, pitch `atan(1/√2)`=35.264° — which is exactly what produces the 2:1 diamond grid. Pan and zoom still derive from `G.cam` via `R3.target()` (screen centre inverted through `isoPt`), so existing pan/zoom/minimap-jump/clamping still drive the 3D view; **rotation is the only new axis**. Drag to rotate, shift-drag to tilt, R to reset — bound on `#view3` only, so the 2D input path is untouched.
  - **The `gl.depthRange` split was REMOVED again** when the real camera landed. It existed to emulate 2D painter order while depth was a fake tile key. Depth is now real, so terrain occluding something behind a hill is correct, not a bug.
  - **CAMERA GEOMETRY — three errors found by measuring, not by eye. Do not re-derive these by hand:**
    1. **pitch is 30° (`asin(IH/IW)`), NOT `atan(1/√2)`=35.264°.** 35.264° is *true* isometric (equal foreshortening on all three axes); this game draws a **2:1 dimetric** grid (IW 26 / IH 13), which is 30°. The wrong angle stretched everything vertically by 2/√3 = 1.1547.
    2. **`m4look`'s right vector is `(-f.z, 0, f.x)`** = `cross(f,(0,1,0))`. It was first written `(f.z,0,-f.x)` — i.e. LEFT — which mirrored the world. That was initially "fixed" by setting homeYaw 180° round, which papered over the ground axes but **cannot** compensate world Y, so hills projected DOWNWARD. Symptom to remember: ground looks fine, height goes the wrong way ⇒ suspect the right/up basis, not the yaw.
    3. **`R3.HS`** converts a 2D "height in pixels" to world tiles so a 10px hill projects to exactly 10px at the home pitch: `1/(cos(30°)·PPT)`. It is a **constant**, not a function of live pitch — height is a real world quantity and is supposed to change apparent size as you tilt.
    - Verified exactly: one tile step projects to (26,13)/(−26,13) and 10px of hill to (0,−10), matching `isoPt`/`elevF*10` to the pixel.
  - **Picking works at any angle (`R3.ray` / `R3.pickGround` / `R3.groundH` / `R3.cornerH`, with `m4inv`/`m4xform`).** Unproject the screen point through the inverse MVP, march the ray against the height field at 0.5-tile stride (one elevation step tall, so a stride cannot skip a feature), then 24 bisections. **`groundH` must mirror `buildMesh` exactly** — same corner average, same HILL — or picks drift from what is drawn. Verified: round-trip (project a tile → pick it back) exact to 1e-5 tiles at five orientations including pitch 1.3 rad, zero misses; and at home it agrees with the 2D `invIso` to 1e-5 over 81 samples.
  - **`groundH` MUST interpolate on the mesh TRIANGLE, never bilinearly.** `buildMesh` emits `(a,c,b),(b,c,d)`, so the split diagonal runs along `tx+tz=1`. The first version used bilinear and a workflow proved it disagrees with the drawn surface by up to **1.25px on saddle quads** (exhaustive over all 512 3×3 elevation patterns) = ~0.11 tiles of pick slip at the pitch floor — clicks landing off what is on screen. `buildMesh`'s private copy of the height rule is deleted; both now call `R3.cornerH`. **Never let a second copy of that formula exist** — the drift would be between where things are drawn and where clicks land.
  - **`PITCH_MIN` 0.35 / `PITCH_MAX` 1.45 guard real failures, not taste.** Below `atan(HILL*HS)`=0.3043 a descending ray can be shallower than the terrain slope, so `ray.y - groundH` stops being monotonic and the bisection brackets the WRONG crossing (measured monotone at 0.35/0.30/0.22, NOT at 0.12). At exactly π/2 the view direction is parallel to world up, `cross(f,(0,1,0))` is the zero vector and `m4look` normalises it to **NaN — whole matrix, blank screen**. Clamp lives in `setPitch` so no path can reach a degenerate camera. The first drag handler allowed 0.12–1.50, i.e. past BOTH.
  - **`pickGround` searches a bounded slab, not an open march.** `G.elev` is binary, so the height field is a 0.314-tile slab and the ray always descends: search exactly `[t0,t1]` (slab top → y=0), 2-3 half-tile steps. The first version marched up to `MAP*3` = 384 steps and could still dead-end and return null. Below the slab there is only the y=0 plane, which a descending ray meets exactly once, so a point is returned for **every** screen pixel; callers decide whether it is on the board.
  - Verified after those fixes: `groundH` matches the drawn surface to **0px**; clamps hold and the matrix stays finite at the ceiling; round-trip **393 samples over 6 yaws × 4 pitches × 3 zooms, 0 misses, worst 1.8e-5 tiles**.

    - **Mipmaps.** The terrain canvas is NON-power-of-two (e.g. 2496²/2912²), which WebGL1 forbids mipmapping — hence the old LINEAR-only path, which shimmered badly at the zoom floor (a ~2.2× minification of a ~2900px texture, full screen, every frame). ## BLENDER UNIT FORGE — 3D models + animations + sprite sheets (2026-08-17)
**Everything lives in `blender/`, and NOTHING in `tiny-conquerors.html` reads it yet.** The game is untouched — 2D and 3D renderers both work exactly as before, no sim change, no determinism risk. This is an asset pipeline sitting beside the game, not a renderer change.
- **One script generates all of it: [`blender/tc_forge.py`](blender/tc_forge.py).** There are no hand-modelled source files to keep in sync — the `.blend`s in `blender/blends/` are *output*. Full docs in [`blender/README.md`](blender/README.md).

- **`blender/viewer.html`** plays the sheets — unit/anim/facing pickers, all-8-facings grid, grass/dirt backgrounds, and live re-tint to any of the 8 player colours. Serve with serve2.ps1 and open `http://localhost:8742/blender/viewer.html`.
- **46 units across FIVE rigs** — `man` (23), `horse` (6), `siege` (5: ram, mangonel, scorpion, trebuchet, bombard), `ship` (9: fishing, cog, transport, galley, longboat, fire, demolition, turtle, cannon galleon), `beast` (3: sheep, deer, boar). Four animations each (idle/walk/attack/die), plus `work` for the villager; passive ships and grazing animals skip attack. `man`/`horse` share the costume system; the other three rigs have their own builder and pose set (`b_*`, `s_*`, `sh_*`).
  - **A ship's origin is the WATERLINE, not the keel** — the game draws water over the bottom of the hull, so the anchor must sit where hull meets water.
  - **Siege wheel bones point along +X**, so spinning a wheel is a rotation about its own local Y; `s_walk` turns them exactly 360° per loop, which is what keeps the cycle seamless.
  - **`do_sheets` merges into an existing `atlas.json`** instead of overwriting it. It used to replace the file with only the units in that run, so rendering a second batch with `--units` silently dropped everything rendered earlier even though the PNGs were still on disk.
- **The camera matches the game's projection exactly, so the sheets are drop-in.** IW=26/IH=13 is 2:1, which pins elevation at exactly 30° with an ortho camera. Direction rows map straight onto the sim: **row k == `u._oct` == k from `octPhi()`**, via `psi_k = -(90° + 45k)` on the model. Verified against the game's math — row 2 faces the viewer, row 6 faces away, row 0 faces screen-right.
- **Facings rotate the MODEL, lights stay world-fixed** (warm key upper-left, matching the 2D art note). That's the period-correct behaviour and why a unit walking away is lit differently from one walking toward you.
- Sheet layout: rows top→bottom = octants 0-7, columns = frames, hard 1-bit alpha. Each unit also gets a `_mask.png` (team surfaces white) and a JSON with **`anchorX`/`anchorY` — where the unit's FEET sit in the cell**. Draw with that pixel on the tile, not the cell centre, or everything floats.
- **Art-direction gotchas, each one a bug that already happened:**
  1. **A weapon modelled at the fist is inside the ribcage.** The hand hangs at x=0.21 and the torso is 0.47 wide, so a sword just vanishes. Every weapon needs a `CARRY` rest-pose offset swinging it clear. This was the most visible defect in the first pass.
  2. **Build a bow perpendicular to the arm bone**, along +Y not +Z. Building it "upright" is the obvious choice and it's wrong: raising the bow arm rotates Y→Z, so a Z-built bow ends up lying flat like a horizontal stick.
  3. **A death animation that pivots the body rigidly on its heels walks out of the sprite cell** — a 1.8m man sweeps his head most of a tile. It has to fold (knees buckle, then tip from the kneel).
  4. **Every unit needs a team-coloured surface.** Half the uniques failed this, because their whole costume identity is *not* being uniformed — Woad Raider is bare-chested, Jaguar is gold and tan, Monk is a plain robe. They got sashes and a team-coloured robe hem.
  5. **Realistic proportions are unreadable at 50px.** Heroic only: big head, big hands, wide shoulders, short thick legs, oversized weapons.
  6. **`view_transform` must be `'Standard'`** — AgX/Filmic desaturates the whole thing into mush.
  7. Polearms **thrust**, they don't swing. `atk='thrust'` exists for exactly this; monks use `atk='convert'` since they have `atk:0` in the sim.
  8. **Sculpted beats stacked (2026-08-17, second art pass).** The first version built everything from boxes and read as voxel art. Rebuilt on lofted tubes + joint balls: limbs taper, heads are a skull plus jaw/brow/nose/ears, horses have real barrels and cannon bones, swords have fullers, shields are curved heaters, bows are curved staves. ~1700 polys/unit (was 367) — about what the era shipped. **Shading moved from 3 hard bands to 5 bands + specular on metal**, because those sprites were Phong-shaded then palettized, not cel-shaded; 3 bands reads as a modern flat-shaded toy. Rounded forms smooth-shaded, plate and cloth left faceted.
     - **`Builder.tube` gotchas**: rings are sorted ascending internally (handing them high-to-low flipped the winding and rendered limbs inside-out), and `rot` is applied AFTER the rings are laid out — so under `rot=(-90,0,0)` a ring's `z` becomes world Y and `oy` becomes world −Z. Reusing the rotated barrel's offsets on an unrotated tube parked the horse's caparison a metre off to the side.
     - **A team-colour face has to sit PROUD of the shell it decorates.** The shield's team panel was inset by less than the shell thickness, so it rendered entirely inside the shield and the unit lost its player colour.
     - **A round pauldron at shoulder height reads as a SECOND HEAD** at sprite size. Flatten it (z-scale ~0.5) and add lames instead.
  9. **Surface texture pass (2026-08-17, third art pass).** Mail rings, cloth weave, wood grain, mottled leather, plate wear, fur, straw — all procedural, no UVs, no image files. Plus a `mail=True` costume flag (hauberk skirt + coif + sleeves) and cheap EEVEE ambient occlusion (`use_fast_gi`, AO-only, 0.22m).
     - **Textures sample a baked `rest` vertex attribute, NOT Object/Generated coords.** Every vertex's rest position is written to a FLOAT_VECTOR attribute in `Builder.build()`. Drive the textures from live coordinates instead and the grain swims across the surface as the armature deforms it — at 12fps that reads as boiling static.
     - **Texture must drive a BUMP, not just the albedo.** A ±15% base-colour tint is invisible at 55px. The normal perturbation is what reads: against a hard-banded ramp the terminator wanders across the weave/rings, and that is what the eye calls texture. `BUMP` is per surface kind; the metal specular is wired to the same normal.
     - **Scale texture to the OUTPUT, not the model.** At 36 px/m anything finer than ~0.03m is sub-pixel and aliases to noise. Always verify a texture change at `--cell 128 --ppm 36`; something that looks superb at 240 px/m can be static at 36.
     - `_MAT_BUMP` caches nodes from the live scene, so it must be cleared alongside `_MAT_CACHE`/`_MASK_CACHE` on every `wipe_scene()` or the next unit dereferences freed nodes.
  10. **Baked actions need `use_fake_user = True` or the .blend saves only the last one.** Each action is swapped off the armature as the next is baked, leaving the earlier ones on zero users, and Blender drops zero-user datablocks on save. Caught by opening `knight.blend` and finding `knight_die` alone. Related: `action.fcurves` reads EMPTY on a 4.4+ slotted action — the curves live in `layers[].strips[].channelbags[]` (`action_fcurves()` tries both).
- **ALL 46 UNITS ARE RENDERED** (2026-08-18): `blender/sheets/` holds 180 animations — 180 beauty sheets + 180 team masks + 46 per-unit JSONs + `atlas.json`, ~67MB. Verified programmatically: every sheet is a correct frames×8 grid, every file referenced by the atlas exists, and the mask re-tint works (militia blue sheet 16210 blue/7883 red pixels → red variant 1454/23137).

## SCULPTED 3D UNIT MESHES IN THE WEBGL RENDERER (2026-08-18) — BUILT, NOT DEPLOYED
The Blender models now render as **real geometry in R3**, replacing the boxed-part archetypes. This is the "get away from sprites" path and it is **cheaper than the sprites**: 6.6MB for all 46 units vs 23MB of sheets, and it holds up at any zoom and any camera angle instead of 8 quantised facings. Determinism baselines matched again afterwards; `R3.draw()` measured **1.26ms**.
- **It reuses R3's existing pipeline wholesale.** The export lands in the *same* 11-float vertex layout the boxed archetypes already use (pos3, nrm3, col3, part, teamMix), so it feeds the same shader, the same instanced draw, the same team colour, age variants, shadows, topple and garrison rendering. Only the geometry changed.
- **[`blender/export_r3.py`](blender/export_r3.py)** writes `app/models.bin` + `app/models.json`. It imports `tc_forge` as a library (set `TC_FORGE_LIB=1` to suppress its CLI) and reuses the same builders, so **the models can never drift from the sprites** — one source of geometry.
- **Coordinate + scale conversion, which is where this goes wrong quietly:**
  - R3 is **Y up, X forward**; Blender is **Z up, Y forward**. `(X,Y,Z)_r3 = (y,z,x)_blender` — a cyclic swap, so handedness survives. Any other permutation silently mirrors every unit.
  - **1 world unit = 1 TILE.** R3's boxed man is ~0.8 tall, ours is 1.85m, hence `SCALE=0.432`.
  - **Pivots are per archetype and must describe OUR geometry** — R3's boxed man used hip 0.27 / shoulder 0.47; ours are 0.372 / 0.562. The exporter emits them per unit.
- **Bones map onto R3's part scheme directly** because our rig is rigidly skinned: legs -> parts 2/3, arms -> 4/5, everything else static. A siege engine's `arm` and a ship's `sail` ride part 4, so they swing on attack.
- **`WebGL1 has no baseVertex`** — indices are rebased onto the shared buffer at export time. Miss that and every unit draws unit 0's mesh.
- **Models need 32-bit indices** (`uIdx32`). Without them the boxed meshes carry on unchanged.
- **Archetype mapping walks `UARCH` AND every `AGEV` variant** (77 archetypes covered). Map only the base and a unit reverts to a boxed mesh the moment its owner ages up, which reads as a bug rather than a tier. Elephant / war wagon / conquistador / tarkan / trade cart have no model and keep their boxed art.
- **LOD**: exported at `--lod 0.7` (fewer tube/ball segments than the sprite build, which was rendered at 55px). 133k verts / 65k tris for the whole roster.
